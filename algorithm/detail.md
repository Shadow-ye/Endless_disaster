## 1. 基础设施与全局常量

### 1.1 坐标与时间

全局常量集中于 `src/Types.h:6-10`：

| 常量 | 值 | 含义 |
|------|-----|------|
| `kTile` | 16 | 一个瓦片的像素边长 |
| `kFrame` | 64 | 精灵帧尺寸 |
| `kViewW` / `kViewH` | 480 × 270 | 逻辑视口 |
| `kSimDt` | 1/60 s | 固定模拟步长 |

世界坐标 → 瓦片坐标的换算只用一个整除：`tileOf(v) = floor(v / 16)`（`Types.h:12-14`）。所有网格类算法（寻路、扫雷、迷宫墙）都建立在「瓦片 = 16px」这层离散化之上，物理层则继续使用浮点世界坐标。

朝向量化 `facingDir`（`Types.h:27-39`）：4 向用「绝对分量谁大」判方向，8 向用 `atan2` 除以 45° 并四舍五入到 0..7。

### 1.2 统一噪声 / 随机数基元 `mixHash`

整个项目唯一的「随机源」是一个 32 位整数混合函数（`Types.h:16-23`）：

```cpp
uint32_t mixHash(uint32_t x) {
    x ^= x >> 16; x *= 0x7feb352dU;
    x ^= x >> 15; x *= 0x846ca68bU;
    x ^= x >> 16;
    return x;
}
```

它同时扮演两个角色：

- **噪声函数**：`mixHash(seed ^ mixHash(x) ^ mixHash(y*C))` 直接当「坐标 → 伪随机值」的地形噪声用（无状态、可复现、无内存）。
- **PRNG**：状态式序列 `rng = mixHash(rng + 0x9e3779B9)`（黄金比例增量），`Session::nextRand()`（`Session.cpp:174-177`）、迷宫洗牌（`MazeRuin.cpp:77-82`）、扫雷布雷（`ShallowPool.cpp:64-68`）都用这一条。

> 设计动机：全流程无全局可变随机队列，只有「种子 + 计数器状态」，因此**同一存档种子 + 同一操作序列 → 完全一致的结果**，便于存档、回放与调试。

## 2. 地图生成（无限程序化地形）

**实现**：`TileMap::baseTile`（`TileMap.cpp:158-189`）与合成入口 `TileMap::at`（`TileMap.cpp:123-155`）。

### 2.1 分层结构

地图不是预先生成的大数组，而是**无限可查询的程序化地形 + 稀疏覆盖层**。查询任意 (x, y) 时按优先级依次判定：

```
at(x, y):
  1. 若在迷宫遗迹范围内        → 墙 / 广场 / 迷宫地板      (MazeWall / Plaza / MazeFloor)
  2. 若在扫雷棋盘格上          → 强制平地 Grass
  3. 若在浅水圆圈内            → Shallow
  4. 否则取 baseTile(x, y)，再按浅水清空带抹平障碍
```

`baseTile` 内部的优先级（`TileMap.cpp:158-189`）：

```cpp
Tile baseTile(x, y):
  if (scorched(x, y))            return Dirt;      // 核爆烧焦层（持久化）
  if (在迷宫外圈 kClearMargin 内) return Grass;     // 迷宫四周清空，保证唯⼀入口通畅
  if (x*x + y*y <= 64)           return Grass;     // 出生点 8 格半径强制草地
  // —— 以下为 hash 噪声地表 ——
  pond   = mixHash(seed ^ 0x51 ^ mixHash(x>>2) ^ mixHash((y>>2) * 0x9e3779b1));
  if (pond%100 < 12 && (x&3) < 2 && (y&3) < 2)  return Water;   // 4×4 超块内的 2×2 水塘
  clump  = mixHash(seed ^ 0x99 ^ mixHash(x>>1) ^ mixHash((y>>1) * 0x85ebca6b));
  if (clump%100 < 7)  return (clump & 1) ? Rock : Bush;          // 2×2 超块的岩石 / 灌木丛
  h = mixHash(seed ^ mixHash(x * 0x85ebca6b) ^ mixHash(y));
  if (h%100 < 14)  return Dirt;                                  // 散落沙地
  return Grass;
```

### 2.2 关键技巧：超块聚合（block aggregation）

噪声不是逐格独立采样，而是先在**超块坐标**（`x >> 2`、`x >> 1`）上求值，再把结果摊到整块：

- **水塘**：按 4×4 超块决定「这块是否有水」，再在块内用 `(x&3)<2 && (y&3)<2` 精确限制成 2×2，于是水塘总是**成块、对齐、边缘整齐**，不会出现碎点噪声。
- **岩石 / 灌木**：按 2×2 超块聚簇，避免障碍物稀疏散布导致通行性支离破碎。

这等价于一个**两级值噪声（value noise）**：低频决定「区域属性」，位运算决定「区域内形状」，但完全不用浮点插值，成本是几次整数乘异或。

### 2.3 通行等级（pass）

`blocks(x, y, pass)`（`TileMap.cpp:195-215`）定义三级通行：

| pass | 含义 | 水 | 岩石 / 灌木 | 迷宫墙 |
|------|------|----|------------|--------|
| 0 | 地面（默认） | 阻挡 | 阻挡 | 阻挡 |
| 1 | 跳跃 / 画面外怪物 | 阻挡 | **可过** | 阻挡 |
| 2 | 飞行 | **可过** | 可过 | **阻挡** |

浅水（`Shallow`）**任何等级都不阻挡**，只通过 `Session::shallowMoveMul` 给生物乘 0.82 减速（`Session.cpp:4561-4569`）。迷宫墙被特意设计成**连飞行也过不去**，保证迷宫结构对一切单位有效。

`blockedAt(x, y, radius, pass)`（`TileMap.cpp:217-231`）用「中心 + 上下左右 4 个半径采样点」近似一个圆形碰撞体，这是典型的**5 点采样 AABB/圆近似**，把圆形碰撞降级为 5 次网格查询。

### 2.4 烧焦层与去重

核爆会把地表烧成 `Dirt`，实现为稀疏覆盖：`unordered_set<int64_t> scorch_` + 顺序数组 `scorchKeys_`（`TileMap.h:47-48`）。`scorchCircle` 用 `dx² + dy² ≤ r²` 双循环写入，写入前用 `insert().second` 去重（`TileMap.cpp:90-112`）——集合保证「同一格只记一次」，数组保证「存档时可顺序序列化」。

瓦片坐标打包成 64 位键：`(int64(x) << 32) ^ uint32(y)`（`TileMap.h:44`），一次整数比较即可完成全部覆盖层查询。

### 2.5 复杂度

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| `baseTile` 单格 | **O(1)** | 固定次数的哈希与取模，无循环 |
| `at` 单格 | **O(1)** | 覆盖层判定 + 至多一次 `baseTile`；烧焦查询为均摊 O(1) |
| `scorchCircle(cx, cy, r)` | **O(r²)** | 外接正方形 (2r+1)² 双循环，实际写入约 πr² 格 |
| 整张可视区域渲染 | **O(V)** | V 为可视瓦片数（480/16 × 270/16 ≈ 510 格） |

**内存**：地形本身 **O(1)**（无存储，纯函数）；烧焦层 O(烧焦格数)；覆盖层 O(1)。

## 3. 怪物寻路（BFS 流场）

**实现**：`PathField`（`PathField.h` / `PathField.cpp`），由 `Session::update` 驱动。

### 3.1 算法：从玩家出发的逆向 BFS 流场

类注释已经把思路写清（`PathField.h:9-11`）：**以玩家为源点做一次广度优先搜索，每个被访问到的格子记录「它的上一层格子」（即离玩家更近一格）；怪物只需查表朝父格走一步，方向天然指向玩家。**

这等价于在**网格图上预计算了一张指向源点的梯度场（flow field）**，代价是一次 BFS，收益是全场怪物（≤14 只）共享同一张场，每只怪物每帧只做一次 O(1) 查表。

```
rebuild(map, px, py):
    parent.clear(); parent[key(px,py)] = key(px,py)
    queue.push(key(px,py))
    while queue 非空:
        (cx, cy) = queue.pop()
        if |cx-px| + |cy-py| >= 42: continue        // 曼哈顿距离剪枝
        for d in {(1,0),(-1,0),(0,1),(0,-1)}:       // 4 邻域
            (nx, ny) = (cx,cy) + d
            if not map.walkable(nx, ny): continue
            if parent 已有 key(nx,ny): continue
            parent[key(nx,ny)] = key(cx,cy)         // 记录父格（更靠近玩家）
            queue.push(key(nx,ny))
```

代码对应 `PathField.cpp:16-52`。

### 3.2 两个关键工程决策

**① 距离剪枝 `kMaxSteps = 42`（`PathField.cpp:26,34-37`）**
BFS 只扩到曼哈顿距离 42 格，超出即停止。这带来两个好处：

- 覆盖范围大约是一个菱形，格数上界 `2 × 42² ≈ 3500`，实际可通行格更少（约 π/2 × 42² ≈ 2770），**内存与时间有硬上界，不随玩家滞留时间增长**；
- 42 格 ≈ 672 px，远大于视口（480×270），已经足够让「画面内 + 一小段画面外」的所有怪物都拿到正确方向；再远怪物本来就用「画面外直冲」逻辑（见 3.4）。

**② 只在玩家跨瓦片时重建（`Session.cpp:3080-3086`）**

```cpp
if (tx != pathTileX_ || ty != pathTileY_) {
    paths_.rebuild(map_, tx, ty);   // 只有玩家脚下格子变了才重建
    pathTileX_ = tx; pathTileY_ = ty;
}
```

玩家按约 96 px/s 移动、瓦片 16px，**每秒钟最多重建约 6 次**（斜向更少）。在 60Hz 模拟下，平均每 10 帧才付一次 BFS 成本，且 BFS 本身在 3000 格以内。

**打破迷宫墙时也会强制重建**（`Session.cpp:1607-1616` 的 `commitBrokenWalls`），因为地形变了，旧流场立刻失效。

### 3.3 数据结构

```cpp
std::unordered_map<int64_t, int64_t> parent_;  // 瓦片键 → 父瓦片键（PathField.h:22）
```

- 键编码：`(x << 32) | uint32(y)`（`PathField.cpp:7-9`），把二维整数对压进单个 64 位键，避免 `pair` 哈希或二维数组越界问题（**世界无边界，不能开二维数组**）。
- 选择 `unordered_map` 而非稠密二维数组：世界是无限的，只为 42 格内的可达区分配内存，天然稀疏。

### 3.4 流场之外的兜底策略

单靠流场不够——怪物可能站在**流场覆盖不到**或**父格方向被实际碰撞体挡住**的位置。因此 `chaseOffscreen`（`Session.cpp:3765-3862`）与常规追击（`Session.cpp:4056-4089`）采用三级降级：

1. **流场直指**：`paths_.nextTile(tileOf(m), ...)` 取父格中心，若探测射线（`probe = 半径+2`）未被挡，直接朝它走（`Session.cpp:3814-3823`）。
2. **贪心选邻格**：`nearestWalkableTile`（`Session.cpp:1729-1748`）在 4 邻格中挑「曼哈顿距离玩家最近」的可走格，把怪物先挪回寻路图上。
3. **侧移 / 后退**：四周都被挡时，尝试 ±45°、±90°、180° 五个方向，取与「朝玩家方向」点积最大且不撞的（`Session.cpp:3837-3855`）。

```
turns = { 朝玩家 左转45°, 右转45°, 左转90°, 右转90°, 反向 }
best = argmax_{t ∈ turns, ¬blocked(t)} dot(t, towardPlayer)
```

**画面外加速**：怪物离视口越远越快，`speed = base + min(100, outside × 0.55)`（`Session.cpp:3793`），基础速度按种类 32~48 px/s（玩家约 96），从而**永远追得上、又不会在画面内显得瞬移**。

碰撞移动用**分轴独立判定**（`Session.cpp:1750-1764`）：

```cpp
if (!blockedAt(x + vx*dt, y, ...)) x += vx*dt;   // 先试 X 轴
if (!blockedAt(x, y + vy*dt, ...)) y += vy*dt;   // 再试 Y 轴（用更新后的 X）
```

这是经典「贴墙滑行」：撞墙时只有一个分量被拒绝，另一个仍生效，怪物沿墙滑走而不会卡死。

### 3.5 复杂度

设 R = 42（剪枝半径），E 为流场中实际可达格数（≤ 2R² ≈ 3500）：

| 操作 | 复杂度 | 触发频率 |
|------|--------|----------|
| `rebuild` | **O(E)** ≈ O(R²)，哈希表常数较大 | 玩家跨瓦片时（≤ ~6 次/秒） |
| `nextTile` 查表 | **O(1)** 均摊 | 每只怪物每帧 |
| `nearestWalkableTile` | **O(1)**（固定 4 邻格） | 流场失败时 |
| 兜底转向 | **O(1)**（固定 5 方向探测） | 被挡时 |
| 单只怪物每帧总成本 | **O(1)** + 常数次 `blockedAt`（每次 5 格查询） | 每帧 |

**内存**：`parent_` ≤ E 项，约 2770 × 16 B ≈ 44 KB 峰值。

## 4. 迷宫生成（迭代 DFS 生成树）

**实现**：`MazeRuin::generate`（`MazeRuin.cpp:62-357`），常量在 `MazeRuin.h:11-17`。源码中每个阶段都用 `// ---- N. … ----` 编号并配有中文注释：0 状态复位、1 建图、2 建生成树、3 广场开单门、4 凿墙、5 开唯一入口、6 求解唯一通路、7 标记 `route`、8 自检。下面按同一顺序展开（其中「随机化」是第 1 步末尾的邻接表洗牌）。

### 4.1 结构参数

| 参数 | 值 | 含义 |
|------|-----|------|
| `kSize` | 33 | 迷宫边长（奇数，保证外墙在偶数边界上） |
| `kPlaza0/1` | 9 / 23 | 中央广场范围，15×15 |
| `kCenter` | 16 | 广场中心 |
| `kClearMargin` | 4 | 迷宫外围清空带宽度 |

33×33 中，**奇数坐标格**（1,3,…,31，共 16×16 = 256 格）是候选通道节点；其中落在广场内的是 8×8 = 64 格，排除后剩 **192 个节点**，加上「广场」作为一个整体节点，共 **193 个图节点**。

### 4.2 算法：图上的迭代式随机 DFS（递归回溯）

迷宫生成本质是**在图上求一棵随机生成树（randomized spanning tree）**，再用树边凿开墙壁。这里用的是**递归回溯法（recursive backtracker）**，但把递归改写成**显式栈**以避免 33×33 规模下爆栈。

**第 1 步：建图（`MazeRuin.cpp:91-136`）**

对每个奇数格 `(x, y)`，沿 4 个「步长 2」方向（`{±2, 0}, {0, ±2}`）连边——因为相邻通道格之间隔着一堵待凿的墙。落到广场的格子，统一连向「广场」这个超级节点。

```cpp
dirs = {(2,0), (-2,0), (0,2), (0,-2)}                          // 步长 2：中间隔一堵待凿的墙
for 每个奇数格 i:
    for d in dirs:
        (nx, ny) = cells[i] + d
        if 广场格(nx,ny):   adj[i] += plaza; adj[plaza] += i     // 广场只登记候选，DFS 阶段不走
        else if id[nx,ny] > i: adj[i] += id[nx,ny]; adj[id[nx,ny]] += i   // 只让小编号连大编号，避免重复加边
```

**第 2 步：随机化（`MazeRuin.cpp:133-136`）**

对每个节点的邻接表做 **Fisher–Yates 洗牌**（`MazeRuin.cpp:83-89`）。洗牌后顺序随机 → DFS 走出随机的生成树 → 每次生成的迷宫形态不同。

**第 3 步：迭代 DFS 抽生成树（`MazeRuin.cpp:138-168`）**

```cpp
seen[0] = 1; stack.push(0);
while stack 非空:
    u = stack.back()
    if cursor[u] >= adj[u].size(): stack.pop(); continue    // 该节点所有边试完，回溯
    v = adj[u][cursor[u]++]
    if v >= plaza 或 seen[v]: continue                      // 广场（含非法下标）留到最后单独接门
    seen[v] = 1; tree.push({u, v}); stack.push(v)           // 选边 + 深入
if 有节点未访问 → 生成失败，返回 false                       // 连通性兜底
```

`cursor[u]` 记录「节点 u 下一条待试边的下标」，这是**迭代版 DFS 的核心技巧**：由于需要「回到 u 时从上次的位置继续」，必须持久化每条边的遍历进度，否则会退化成 O(度数) 次重复扫描。

> 注意 `v >= plaza`（即广场节点）被跳过：广场不参与普通 DFS 扩展，而是**在生成树完成后只接一道门**（下一步），从而保证「进广场有且仅有一条通路」。

**第 4 步：广场开单门（`MazeRuin.cpp:170-186`）**

收集所有「与广场相邻」的节点作为候选门位 `gates`，洗牌后只取**第一个**，加一条树边连到广场。这一步是「**广场唯一入口**」的算法保证（广场在生成树上的度恒为 1）。

**第 5 步：凿墙（`MazeRuin.cpp:188-233`）**

遍历生成树的所有边：

- 普通边 `a—b`：凿开两端格及**中间那格**（`(ax+bx)/2, (ay+by)/2`），因为间隔为 2。
- 广场边：从广场邻近格朝广场方向推一格凿门（按 `cx < kPlaza0 / cx > kPlaza1 / cy < kPlaza0 / cy > kPlaza1` 决定推的方向），并记录 `doorX/doorY`。
- 最后把整个 15×15 广场**全部凿平**（`MazeRuin.cpp:228-233`）。

**第 6 步：外墙开唯一入口（`MazeRuin.cpp:235-265`）**

在 `x==1 / x==31 / y==1 / y==31` 的边界通道节点里随机选一个，向墙外推一格凿开，记录 `entranceX/entranceY`。若候选格同时贴两条边（角点），用一次随机位决定从哪边开。

**第 7 步：求解入口 → 广场（用于第 5 节的通路标记，`MazeRuin.cpp:267-296`）**

在生成树上从入口节点做一次 **BFS** 求父指针，终点为广场节点。因为是**树**，BFS 得到的路径唯一且最短（无环 ⇒ 任意两点间路径唯一 ⇒ 唯一路径必然是最短路径）。

### 4.3 复杂度

| 阶段 | 复杂度 | 说明 |
|------|--------|------|
| 建图 | **O(N · 4)** = O(N) | N = 192，每个节点 4 个方向 |
| 邻接表洗牌 | **O(N)** | Fisher–Yates |
| 迭代 DFS | **O(N + E)** = O(N) | E ≤ 2N（无向），每条边至多被 `cursor` 取一次 |
| 广场开门 | **O(N)** | 扫描邻接表 |
| 凿墙 | **O(N)** | 树边 N-1 条，每条 O(1) |
| 广场凿平 | **O(15²)** = O(225) | 常数 |
| 入口 BFS | **O(N + E)** | 树上一次遍历 |
| 通路回溯 | **O(深度)** ≤ O(N) | 父指针链 |
| `audit` 自检 | **O(N)**（携带「路径计数 ≤ 2」的提前剪枝，见第 5 节） |  |
| **单次生成总计** | **O(kSize²)** = O(1089) | 主要由固定的 33×33 决定 |

其中 N = (kSize-1)/2)² − plazaCells = 192，kSize = 33。

**重试上界**：`Session::spawnRuin`（`Session.cpp:4253-4308`）最多尝试 **40 次**放置（每次换随机中心点与种子），任一环节 `generate` 失败就 `continue`。整体最坏 **O(40 · kSize²)**，但实际几乎总在第 1~2 次成功（生成树一次 DFS 必然连通，失败只可能来自 audit 的极端形态）。

**内存**：`wall` / `route` 各 33×33 = 1089 字节（`uint8`），邻接表 O(N)。

## 5. 迷宫通路（唯一解法路径 + 自检）

「迷宫通路」在游戏中指：**从外墙唯一入口出发，穿过迷宫、经唯一一道门进入中央广场，抵达广场中心的一条（且仅有一条）路线**。它有两层含义——一层是**道路本身**（给玩家导航 / 雷达显示），一层是**算法对道路唯一性的证明**。

### 5.1 道路标记 `route`（`MazeRuin.cpp:298-346`）

`route` 是与 `wall` 同尺寸的 33×33 位图，`1` 表示「在唯一解法路径上」（源码中为第 7 步）。生成方式：

```cpp
// 1. 从广场沿 parent[] 指针回溯到入口，得到节点链 chain（parent[入口] == 入口 时终止）
chain = 回溯(plaza → ... → entranceCell); reverse(chain);

// 2. 标记入口外墙格
mark(entranceX, entranceY);

// 3. 逐段标记：节点格 + 相邻节点之间的中间墙格
for i in chain:
    if node == plaza: break
    mark(cells[node]);
    if next == plaza:
        mark(doorX, doorY);
        // 从门出发，先水平、后垂直，折线走到广场中心
        while x != kCenter: x ±= 1; mark(x, y);
        while y != kCenter: y ±= 1; mark(x, y);
        break;
    mark(mid(cells[node], cells[next]));   // 两节点中点那格（凿墙时已打通）
```

因为路径取自**生成树**（无环图）上的父指针链，所以这条路**结构上不可能有第二条**。`MazeRuin::onRoute(lx, ly)`（`MazeRuin.h:54`）供渲染层查询，雷达与迷宫地图据此画出唯一路线。

### 5.2 唯一性自检 `audit`（`MazeRuin.cpp:365-467`）

生成完成后立即自检，四项全部通过才 `active = true`：

1. **入口恰好 1 个**：扫描四条外墙上的可通行格，计数必须为 1，且等于记录的 `entranceX/Y`（`MazeRuin.cpp:369-387`）。
2. **门恰好 1 道**：扫描广场四周一圈（`kPlaza0-1` ~ `kPlaza0/1+1` 的边框格），可通行格计数必须为 1，且等于 `doorX/doorY`（`MazeRuin.cpp:388-408`）。
3. **广场全通**：15×15 内不允许存在 `wall != 0`（`MazeRuin.cpp:409-416`）。
4. **入口到门恰好 1 条路径**：从入口出发做一次 **DFS 路径计数**，但**一旦数到 2 就立刻停止**（`while (!walk.empty() && paths < 2)`）。

第 4 条是关键，实现为**显式栈的 DFS + 每帧 4 邻域游标**（`MazeRuin.cpp:418-466`），并用 `seen` 数组做路径内去重、回溯时清除（`seen[...] = 0`）。可走格由 `floorOutside` 判定：**广场内部被排除**，门是广场边界，路径走到门即算抵达终点，避免绕广场一圈被误算成多条路径：

```cpp
walk.push({entrance, next=0}); seen[entrance] = 1;
while (walk 非空 && paths < 2):
    f = walk.back()
    if (f 是门): paths++; seen[f] = 0; walk.pop(); continue     // 找到一条完整路径，回溯续找
    if (f.next >= 4): seen[f] = 0; walk.pop(); continue         // 4 个方向试完，回溯
    (nx, ny) = f + nbrs[f.next++]                               // 先自增游标，回溯后从下一方向继续
    if 不是广场外地板 或 seen: continue
    seen[nx,ny] = 1; walk.push({nx, ny, 0})
return paths == 1
```

**为什么不用普通 DFS「visiting 集合」判环**：目标是统计**简单路径条数**，不是判可达。计数型 DFS 需要在回溯时**撤销** `seen`（恢复现场），这是「枚举简单路径」的标准写法。加上 `paths < 2` 的提前退出，最坏仍是 O(V+E)，实际只走完一条路径 + 找到第二条的一小段就返回。

**与最短路径的关系**：生成树上入口到广场的路径唯一，因此「唯一解路径」同时也是**最短路径**——`route` 标的就是这条最短路；`audit` 的第 4 项则在墙位图上独立复核「这样的路径确实只有一条」，两者分别从**构造**和**验证**两侧锁死了唯一性。

> 设计动机：迷宫生成是随机的，理论上可能出现「广场被两个通道同时连上」这类破坏关卡设计的形态。与其事后调试，不如**生成即验证、不合格即丢弃重生成**，把「唯一通路」变成强保证而非期望。墙上还能被玩家的爆破 / 次元斩打破，但那是玩家主动改写地形，与关卡初始设计意图无关。

### 5.3 复杂度

| 操作 | 复杂度 |
|------|--------|
| 通路标记 `mark` 链 | **O(kSize)**（链长 ≤ N，含到广场中心的水平竖直段） |
| `audit` 四项检查 | **O(kSize²)**（扫外墙 O(kSize)、扫广场边框 O(kSize)、扫广场 O(kSize²)、路径计数 O(V+E) 且 ≤ 2 条路径提前退出） |
| `onRoute` 查询 | **O(1)** |

## 6. 扫雷（位掩码 + 首击保护 + 洪泛展开）

**实现**：`ShallowPool`（`ShallowPool.h` / `ShallowPool.cpp`）。棋盘 5×5、5 颗雷，摆在浅水区圆心，玩家**跳跃起跳与落地各揭示一次**脚下格（`Session.cpp:3167-3172`、`3352-3355`）。

### 6.1 数据结构：三个 32 位位掩码

```cpp
uint32_t mineMask;       // 雷位
uint32_t revealedMask;   // 已揭示的安全格
uint32_t triggeredMask;  // 已被踩过的雷
```

格子下标 `idx = ly * 5 + lx`（0..24），位 `1u << idx`。25 格只需 25 位，**三个 `uint32` 完整描述棋局状态**：判位、置位、计数全部是位运算，无动态内存、无二维数组、可整块存档（`Session.cpp:776-779`）。

```cpp
bool isMine(lx, ly)      { return mineMask     & (1u << (ly*5 + lx)); }
void popCount(uint32_t v){ while (v) { v &= v - 1u; ++n; } }   // 每次消掉最低位 1
```

`popCount` 用 `v &= v - 1` 的**消最低位技巧**，迭代次数 = 置位个数（≤ 25），比逐位循环 32 次更省（`ShallowPool.cpp:9-16`）。

### 6.2 布雷：种子化 Fisher–Yates（`ShallowPool.cpp:55-82`）

```cpp
cells = [0, 1, ..., 24]
rng = seed
for i = 24 → 1:
    j = mixHash(rng + 0x9e3779b9) % (i + 1)     // 无模偏置担忧（25 很小，误差可忽略）
    swap(cells[i], cells[j])
前 5 个 → 写入 mineMask
```

**同一颗种子 ⇒ 同一张棋盘**，与存档 / 读档一致性要求吻合。洗牌保证 5 颗雷在 25 格中等概率且不重复。

### 6.3 首击保护：`relocateMine`（`ShallowPool.cpp:162-194`）

经典扫雷的「第一下必定安全」在此实现为**踩到雷时把雷搬走**，而不是重新布雷（重新布雷会破坏既有的 `revealedMask`）：

```cpp
if (revealedMask == 0 && triggeredMask == 0) {   // 尚未翻开任何格子 = 第一击
    relocateMine(lx, ly);
} else {
    triggeredMask |= bit; return 2;               // 非首击踩雷：记为触发
}
```

`relocateMine` 的搬移策略有优先级：

1. **优先搬到「原格 3×3 邻域之外」的第一个空位**——这样首击格周围没有雷，`adjacentMines == 0`，洪泛必然连锁掀开一片，体验上「开局就开阔」；
2. 若 25 格全满（不可能，5 雷 < 25），退化为「任意空位」。

### 6.4 展开：迭代式洪泛填充（`ShallowPool.cpp:196-251`）

翻开一格后，从该格向外扩散：

```cpp
stack.push(idx)
while stack 非空:
    idx = stack.pop()
    if (revealedMask & bit) 或 (mineMask & bit): continue   // 已翻 / 是雷 → 停
    revealedMask |= bit                                     // 揭示本格
    if (adjacentMines(cx, cy) != 0): continue               // 数字格：揭示但不扩散
    for 8 邻域 (nx, ny) 合法:  stack.push(ny*5 + nx)         // 空白格：继续扩散
```

这是标准扫雷规则：**相邻雷数为 0 才继续外扩，遇到数字格只揭开不再扩散**。用显式 `std::vector` 当栈而不是递归，避免 25 层递归；`revealedMask` 兼作 visited 标记，**不需要额外 visited 数组**。

`adjacentMines`（`ShallowPool.cpp:135-148`）是 3×3 双循环（跳过自身），最多 8 次 `isMine` 位测试。

### 6.5 胜负判定（`ShallowPool.cpp:158-160`）

```cpp
boardComplete() = revealedCount() >= safeTotal()   // safeTotal = 25 - 5 = 20
               || triggeredCount() >= kMines       // 或者 5 颗雷全踩完
```

`safeTotal = kBoardSize² - kMines = 20`，两条完成路径：**排空所有安全格**，或**踩遍所有雷**（游戏中后者伴随扣血与 SAN 上限削减，`Session.cpp:55-56`）。

### 6.6 复杂度

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| `generate` 布雷 | **O(K)** = O(25) | Fisher–Yates |
| `relocateMine` | **O(K)** = O(25) | 线性扫描空位 |
| `adjacentMines` | **O(1)** | 固定 8 次位测试 |
| `reveal` 洪泛 | **O(K)** = O(25) | 每格至多入栈常数次（8 邻域），实际 ≤ 25 格揭示 |
| `revealedCount` / `triggeredCount` | **O(K)** ≤ O(25) | `popCount` |
| `boardComplete` | **O(K)** | 两次 `popCount` |
| 单次 `revealBoardTile` 总成本 | **O(K)** = O(25) | 常数级别，可忽略 |

**内存**：3 × 4 字节 = 12 字节。这是全项目**性价比最高的算法实现之一**：25 格棋局用位掩码压到 12 字节，判定与展开都在个位数微秒内完成。

## 7. 机甲人蜂群（Boid 群体行为）

**实现**：`Session::castSwarm` / `Session::updateDrones`（`Session.cpp:1971-2131`），参数在 `Session.cpp:1884-1900`。

### 7.1 设计目标

技能「无人机蜂群」召唤 **6 架无人机**，要求它们：

- 看起来像**一群**（不重叠、方向一致、整体跟随、绕着玩家盘旋）；
- 有敌时**一架接一架地扑出去**攻击（错峰出击），而不是整齐划一冲出去；
- 无敌时**环绕玩家巡逻**。

这正是 Reynolds 的 **Boid 模型**（分离 / 对齐 / 聚拢）加一层**目标牵引（seek）**。代码注释也明确写出「分离 + 对齐 + 聚拢」（`Session.cpp:1996`）。

### 7.2 参数表（`Session.cpp:1890-1900`）

| 常量 | 值 | 含义 |
|------|-----|------|
| `kDroneCount` | 6 | 无人机数量 |
| `kDroneLife` | 12 s | 单机存活时间 |
| `kDroneNeighbor` | 36 px | 邻居感知半径 |
| `kDroneSeparation` | 12 px | 分离力作用半径 |
| `kDroneSeekRange` | 240 px | 索敌半径 |
| `kDroneOrbitRadius` | 26 px | 无目标时的环绕半径 |
| `kDroneIdleSpeed` / `kDroneAttackSpeed` | 150 / 230 px/s | 巡航 / 攻击最大速度 |
| `kDroneMaxAccel` | 900 px/s² | 加速度上限 |
| `kDroneBlast` | 26 px | 爆炸溅射半径 |

### 7.3 算法：n² 邻域 → 三力合成 → 目标牵引 → 限幅积分

**第 1 步：全局索敌（`Session.cpp:2001-2012`）**

在 `monsters_` 中找**离玩家最近**且距离 < `kDroneSeekRange` 的怪物，作为蜂群共享的 `target`。O(M)。

**第 2 步：n² 邻域统计（`Session.cpp:2014-2049`）**

对每架 i，遍历所有 j ≠ i：

```cpp
d = drone[i].pos - drone[j].pos
if |d| >= kDroneNeighbor: continue          // 感知半径外忽略
neighbors++
ali  += drone[j].vel                          // 对齐：累加邻居速度
coh  += drone[j].pos                          // 聚拢：累加邻居位置
if |d| < kDroneSeparation:                    // 分离：越近推力越大
    push = (kDroneSeparation - |d|) / kDroneSeparation
    sep += d / |d| * push
```

**第 3 步：三力加权合成（`Session.cpp:2050-2055`）**

```cpp
ax = sep.x * 700.f;                                  // 分离：最高权重，防重叠
if (neighbors > 0) {
    ax += (ali.x / neighbors - vx) * 1.5f            // 对齐：向邻居平均速度靠拢
        + (coh.x / neighbors - x)  * 3.f;            // 聚拢：向邻居质心靠拢
}
```

权重 700 : 3 : 1.5 的悬殊比例体现经典 Boid 调参原则：**分离必须绝对优先**（防穿模），聚拢次之，对齐最弱（避免整群僵化成一条线）。

**第 4 步：目标牵引 + 错峰出击（`Session.cpp:2056-2075`）**

```cpp
attack = target && drone.age > 0.25f + 0.12f * drone.slot;   // 按编号错峰
if (attack):  goal = target.pos;   speed = kDroneAttackSpeed;
else:         goal = player.pos + orbit(time * 1.6 + slot * 2π/6, kDroneOrbitRadius);
              speed = min(kDroneIdleSpeed, |goal - x| * 5);   // 近处减速，避免抖动
ax += (normalize(goal - x) * speed - v) * 5.f;                // 速度匹配式 seek
```

- **错峰出击**：`drone.age > 0.25 + 0.12 × slot` 让 6 架按槽位编号依次（每架晚 0.12s）脱离编队扑向敌人，视觉上是「一架接一架」。
- **环绕巡逻**：目标点取玩家周围半径 26 的**圆周上随时间旋转的点**，`time_ * 1.6` 给出角速度，`slot × 2π/6` 让 6 架均匀分布在圆周上。
- **近处减速**：`min(idle, dist × 5)` 是一阶临界阻尼式刹车，目标越近速度越小，避免在目标点附近来回震荡。

**第 5 步：加速度限幅 + 显式欧拉积分（`Session.cpp:2076-2097`）**

```cpp
if (|a| > kDroneMaxAccel) a *= kDroneMaxAccel / |a|;   // 限加速度
v += a * dt;
if (|v| > maxSpeed) v *= maxSpeed / |v|;               // 限最大速度
x += v * dt;   age += dt;   life -= dt;                // 积分 + 生命周期
```

加速度限幅保证转向平滑（不会瞬间反向），速度限幅保证冲刺不超过设定巡航 / 攻击速度。这是标准的 **半隐式欧拉积分**。

**第 6 步：碰撞与销毁（`Session.cpp:2100-2130`）**

- 撞 `MazeWall` → 就地爆炸（`explodeDrone(drone, harmful=true)`，半径 26 溅射 + 击退），但**拆不掉迷宫墙**（关卡设计：拆墙要等 boss 倒下）；
- 被敌方弹幕命中 / 接触怪物 → 爆炸；
- `life ≤ 0` → 自然消散（无害爆散）；
- 最后 `remove_if` + `erase` 一次性批量删除（避免循环中删除导致的迭代器失效）。

### 7.4 复杂度

n = 6（固定），m = 怪物数 ≤ 14，b = 弹幕数：

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 全局索敌 | **O(m)** | 线性扫描怪物 |
| n² 邻域统计 | **O(n²)** = O(36) | 固定 36 对，常数 |
| 力量合成 + 限幅 + 积分 | **O(n)** | 每架 O(1) |
| 撞墙 / 弹幕 / 怪物碰撞 | **O(n · (b + m))** | 每架线性扫弹幕与怪物 |
| **每帧总计** | **O(n² + n(b + m)) = O(b + m)** | n 为常数 6 |

因为 `kDroneCount` 是编译期常量，蜂群算法在**渐进意义上等价于 O(b + m)**，每帧成本与无人机数量无关——这是「用小规模固定 n 换掉 n² 隐患」的工程取舍。

**内存**：`std::vector<Drone>` ≤ 6 个（每个约 6 个 float），另有每帧临时 `accX/accY/attacking` 三个长度 6 的数组。

> 附带说明：**次元斩时缓**会统一缩放这一层——`worldDt = dt * dimensionSlowScale()`（`Session.cpp:3090-3093`），无人机、怪物、弹幕一起进入 0.22 倍速，而玩家的输入计时照原速走。`dimensionSlowScale` 在收尾 0.2s 内线性拉回 1.0，避免「斩完啪地恢复」（`Session.cpp:2550-2556`）。

## 8. 其它配套算法

### 8.1 怪物互推分离（`Session.cpp:4092-4126`）

怪物之间用 O(m²) 两两分离，避免叠在一起：

```cpp
for i < j:
    if |pos[i] - pos[j]| < 14:
        push = (14 - d) * 0.5
        若落点可站立（blockedAt 检查）: 各退 / 各进 push/2
```

关键细节：**先验证落点站得住**再位移，否则怪物会被挤进水或墙里再也出不来（这是 v0.5.3 修复的 bug）。`m ≤ 14`，所以 O(m²) ≤ 196 是常数级。

### 8.2 刷怪调度（`Session.cpp:3586-3642`）

- 刷怪间隔 `spawnCd = max(0.85, 2.6 - time × 0.012)`（`Session.cpp:3615`）——**随时间线性收紧、有下限**，形成难度曲线；
- 存活上限 `alive >= 14` 即停刷（`Session.cpp:3622`）；
- 怪物种类按「时间门槛 + 100 面骰」概率解锁（`Session.cpp:3630-3640`）：15s 起骷髅、20s 起施法怪、25s 起蘑菇、30s 起机器人小兵；
- 出生点 `findSpawn`（`Session.cpp:3568-3584`）：**以玩家为圆心、半径 170~310、随机角度**撒点，最多 24 次尝试，要求落在可走地面且不在迷宫内——即**拒绝采样（rejection sampling）**，在环带上取均匀角度。

### 8.3 迷宫墙破坏（`Session.cpp:1597-1700`）

提供三种形状的破墙查询，都是「以玩家为原点，在包围盒内逐格判定」：

| 函数 | 形状 | 判定 |
|------|------|------|
| `breakMazeWallsRadius` | 圆 | `dist ≤ radius` |
| `breakMazeWallsCone` | 扇形 | `dist ≤ range` 且 `dot(dir, facing) ≥ minDot` |
| `breakMazeWallsBeam` | 矩形光束 | `0 ≤ along ≤ range` 且 `perp ≤ halfWidth` |

三者都先取包围盒 `span = ceil(range / kTile) + 1` 做双循环，单格 O(1)。破坏后 `commitBrokenWalls` 会 `syncRuinMap` + **重建寻路流场**（地形变了）。

### 8.4 次元斩六芒星路径（`Session.cpp:2562+`）

「次元斩」的斩击路线是**六芒星（两个正三角形叠加）**，预先把 7 个节点（中心起手点 + 6 个顶点）按「上 → 右下 → 左下 → 右上 → 下 → 左上」排序，即依次走完两个三角形的顶点序列。运行时用脚本插值在节点间移动，属于**关键帧脚本动画**而非物理模拟。

### 8.5 精灵图集切片与染色（`Sprites.cpp:9-64`）

- 图集切片：`frames = width / size`、`dirs = height / size`，纯整除网格切分（`Sprites.cpp:9-20`）；
- 染色复刻：用 `(299·R + 587·G + 114·B) / 1000` 的**感知亮度权重**重算灰度，再按目标色调重新着色；结果用 `QHash<QRgb, QImage>` 缓存，**同一颜色只算一次**（`Sprites.cpp:29-64`）。

## 9. 复杂度总览

设：R = 42（寻路剪枝半径），W = 33（迷宫边长），K = 25（棋盘格数），n = 6（无人机数，常量），m ≤ 14（怪物数），b = 弹幕数，V = 可视瓦片数。

| # | 算法 | 单次 / 每帧复杂度 | 触发频率 | 内存 |
|---|------|------------------|----------|------|
| 1 | 地形查询 `baseTile` / `at` | **O(1)** | 每次查询 | O(1)（纯函数） |
| 2 | 圆形烧焦 / 破墙 | **O(r²)** | 事件驱动 | O(烧焦格) |
| 3 | 怪物寻路 `rebuild` | **O(R²)** ≈ O(3500) | 玩家跨瓦片（≤ 6 次/s） | O(R²) ≈ 44 KB |
| 4 | 寻路查表 `nextTile` | **O(1)** | 每怪每帧 | — |
| 5 | 单怪每帧运动（含兜底转向） | **O(1)** + 常数次 5 点碰撞 | 每帧 | — |
| 6 | 迷宫生成 | **O(W²)** = O(1089) | 每个迷宫一次（最多重试 40） | O(W²) ≈ 2 KB |
| 7 | 迷宫通路标记 | **O(W)** | 与生成同步 | 复用 route |
| 8 | 迷宫自检 `audit` | **O(W²)**（路径计数 ≤ 2 提前退出） | 与生成同步 | 复用 seen |
| 9 | 扫雷布雷 `generate` | **O(K)** = O(25) | 每个浅水区一次 | 12 B |
| 10 | 扫雷展开 `reveal`（洪泛） | **O(K)** = O(25) | 每次跳跃起 / 落 | — |
| 11 | 蜂群 Boid `updateDrones` | **O(n² + n(b+m))** = **O(b+m)** | 每帧 | O(n) |
| 12 | 怪物互推分离 | **O(m²)** ≤ 196 | 每帧 | — |
| 13 | 刷怪调度 | **O(m + 24)** | 每 0.85~2.6 s | — |
| 14 | 固定步长主循环 | **O(steps × 全局每帧成本)**，steps ≈ 1~3 | 每次渲染帧 | — |

**整体结论**：所有网格类算法（地图、迷宫、扫雷）都被约束在**固定规模常数**上（33×33、25 格），唯一随玩家行为增长的是寻路流场，但它有 **R² = 1764 的硬上界**且只在跨格时重建。因此游戏在任意长的存活时间下，**CPU 与内存占用都不随时长增长**——这是「无尽生存」玩法成立的前提。

## 10. 性能与确定性设计要点

贯穿上述算法的几条设计原则：

1. **无限世界用「纯函数地形 + 稀疏覆盖层」**：地图不落盘、不预生成，`baseTile` 是 O(1) 的坐标→地形函数，任何位置随查随得；只有玩家改动过的部分（烧焦、破墙）才需要存储。

2. **共享计算替代逐个体计算**：14 只怪物共用一个 BFS 流场，而不是各自跑 A*。一次 O(R²) 换 14 次 O(1) 查表，且重建频率受玩家移动速度自然限制。

3. **固定规模 + 位掩码**：扫雷用 3 个 `uint32` 描述整局，25 格洪泛在 12 字节数据上完成；蜂群 n 固定为 6，n² 退化为常数。凡是「设计上就这么大」的问题，都用最紧凑的定长结构。

4. **生成即验证（generate-and-validate）**：迷宫随机生成后必过 `audit` 四项检查（入口唯一、门唯一、广场全通、入口到门恰一条路），不合格直接重生成。把玩法约束（唯一通路）写进算法的不变式，而不是事后修补。

5. **显式栈替代递归**：迷宫 DFS（193 节点）、扫雷洪泛（25 格）、迷宫路径计数 DFS 全部使用 `std::vector` 显式栈，避免递归深度与爆栈风险，也方便在回溯时恢复 `seen` 现场。

6. **固定步长 + 状态式种子 PRNG**：模拟固定 1/60 s 推进（`kSimDt`，`GameWidget.cpp:1150-1167` 按真实帧时长算出整数步数再均分 `dt`），所有随机来自「种子 + `mixHash` 计数器」，**同种子同输入必得同结果**，为存档、读档、调试与未来回放奠定基础。

7. **分级降级容错**：寻路失败 → 贪心选邻格 → 侧移 / 后退；碰撞用分轴独立判定实现贴墙滑行；被挤进障碍时按 `pass` 逐档放行迈出来（`Session.cpp:1720-1727`、`3796-3799`）。算法不会因为边界情况而让单位卡死。
